05 · Research applied
FindingSourceWhat this merchant does about it
Agents fabricate product ids and misattribute specs and prices with no provenance in tool responses; best LLM reaches 11% retrieval F1 vs 26% for humans.ShoppingComp, arXiv 2511.22978Every field is {value, source, as_of}; POST /verify grounds a claim as MATCH / MISMATCH / UNKNOWN / CONFLICT before the agent acts.
Largest failure class: unverified attributes inferred from product titles; early wrong preferences cascade.Shopping Companion, arXiv 2603.14864Nothing is derived from name or description. A title that says “Blue” with no colour on record verifies as UNKNOWN.
Decisions need a protected envelope with reasons, freshness horizon and evidence hashes; payment authority is evaluated last; stale evidence can never project as allowed; material state changes force revalidation.Decision-centred reference architecture, arXiv 2607.18347Every quote, checkout and payment returns an envelope with evidence_hash and decision_hash. Gate order is fixed: actor → mandate → cart → live revalidation → caps → rail. Price or stock drift since the quote refuses with REQUIRES_REVALIDATION.
Final state alone hides 11.5% of errors; evaluate the trajectory across Observe, Decide, Ground, Submit, Execute; keep persistent records.Agentic Commerce World, arXiv 2608.02441Each ledger row is tagged with its stage, and the chain verifies end to end.
Agent purchases should be three signed mandates: intent, cart, payment; human-present payment is the safe default.Google AP2 specificationMandate = intent mandate (caps, expiry, scope). Signed quote = cart mandate. Razorpay Checkout completed by a person = payment mandate.
Merchants cannot tell agents from bots, so fraud stacks block legitimate agents.Track briefLegitimate agents present an identity and a signed mandate; unidentified callers get 401 and are logged.
